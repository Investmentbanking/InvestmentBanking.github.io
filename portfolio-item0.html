Transparent Message Control

React & TypeScript Messaging Prototype

Project Overview

This dissertation investigates how private one-to-one messaging platforms can provide users with greater control over messages both before and after transmission.

I designed and developed a functional React messaging prototype centred around two message-control mechanisms: a temporary pre-send delay that gives users an opportunity to undo a message before delivery, and a more transparent post-send revocation experience for withdrawing content after it has been sent.

The project combines software development with requirements gathering, iterative prototyping and user evaluation to explore how message-control mechanisms can balance user agency, transparency, trust and usability.

The Problem

Sending a digital message is often effectively instantaneous, while meaningful control is usually offered only after transmission has already occurred.

Post-send deletion can also create uncertainty. Removing a message from a conversation does not necessarily mean its contents were never seen, displayed in a notification or otherwise captured.

This project therefore explored whether message control could be improved by considering the entire message lifecycle: providing an opportunity to reconsider a message before delivery while also communicating the limitations of post-send deletion more transparently.

Core Features

Pre-Send Undo Window

Messages can enter a temporary pre-delivery state, giving the sender a short opportunity to cancel transmission before the message is delivered.

Visible Sending Countdown

A visible countdown communicates how long remains before delivery, making the temporary undo period understandable rather than hiding the delay.

Configurable Undo Settings

Users can configure their preferred undo duration, allowing the level of pre-send friction to be adjusted rather than forcing a single behaviour.

Global & Per-Chat Controls

A default undo preference can be configured globally while individual conversations can override that setting when different behaviour is preferred.

Transparent Message Deletion

Post-send controls distinguish between removing content from the sender's own interface and attempting to withdraw it from both participants' conversation histories.

Message Status Feedback

Visual feedback communicates message lifecycle states such as sending, delivered, seen, cancelled and removed.

System Architecture

The prototype uses a modular client-side React architecture with application logic separated from interface components.

Centralised Message State

A custom React hook, useChatState, centralises conversations, message states, sending behaviour, undo functionality, deletion logic and user interactions.

Modular Components

The interface is divided into focused components including ChatList, ChatMessages, MessageBubble, MessageInput and ChatModals.

Typed Data Models

Shared TypeScript definitions provide consistent structures for messages, contacts and application state across components and tests.

Unidirectional Data Flow

State and event handlers are passed through component props, keeping data flow predictable and maintaining clear boundaries between interface and application behaviour.

Message Lifecycle

Messages are represented as structured objects containing information including their content, timestamp, sender identity and current status.

01 — Compose

The sender writes a message through the messaging interface and initiates the send action.

02 — Pending

When an undo window is enabled, the message temporarily enters a pre-delivery state and a countdown is shown.

03 — Undo or Deliver

The sender can cancel during the temporary window. Otherwise, the timed transition completes and the message moves to its delivered state.

04 — Post-Send Control

Once sent, deletion controls allow the user to manage the message while receiving clearer information about what deletion can and cannot guarantee.

Research Focus

The design and implementation were guided by four central questions about user control in private messaging.

End-to-End Message Control

How can messaging systems better support user control across both the pre-send and post-send stages?

Trustworthy Revocation

How can post-send message revocation provide clearer, more reliable and more trustworthy user control?

Pre-Send Reconsideration

Can a short undo window meaningfully support users who want to reconsider a message immediately after pressing send?

User Perception

How do users perceive and compare deletion, transparency features and pre-send undo mechanisms?

Research & Design Process

The system was developed through an iterative, user-centred process. Initial research examined existing work around consent revocation, message persistence, transparency and friction within digital communication.

Semi-structured interviews were then used to explore user experiences of message regret, deletion and perceived loss of control after sending.

Findings from the research informed successive prototype designs. Rather than developing the final interface immediately, concepts were progressively evaluated and refined before being implemented as a functional React prototype.

Iterative Evaluation

The project used four rounds of research and evaluation, allowing findings from each stage to influence the next iteration of the design.

Round 1 — Requirements

Initial research investigated existing messaging behaviours, user expectations and limitations in sender control to establish design requirements.

Round 2 — Early Prototype

Early interaction concepts were evaluated to identify usability problems and determine how users interpreted the proposed message-control mechanisms.

Round 3 — High Fidelity

A more refined interface was evaluated to examine the clarity of the interaction flow, controls and feedback before functional implementation.

Round 4 — Functional Prototype

The implemented React prototype was evaluated to assess the final pre-send and post-send mechanisms in an interactive messaging environment.

Engineering & Design Decisions

Separating Logic from the Interface

Messaging behaviour involves several interconnected states. Centralising this logic inside a custom React hook prevented message lifecycle behaviour from becoming tightly coupled to individual visual components.

Modelling Pre-Send Behaviour

The undo mechanism required messages to exist in a temporary state between pressing send and final delivery. Timed state transitions were used to model this lifecycle while keeping the countdown and cancellation controls synchronised with the underlying message state.

Balancing Friction and Control

Increasing the time before delivery can provide more opportunity for reconsideration, but excessive delay can interfere with the speed users expect from messaging. Configurable undo durations were therefore explored rather than enforcing one fixed delay.

Designing Honest Deletion Feedback

Post-send deletion was designed to avoid implying that digital content can always be completely recovered or erased. The interface instead communicates limitations and distinguishes between different removal actions.

Implementation Approach

React was used for the dynamic interface and state-driven rendering required to represent changes throughout a message's lifecycle. TypeScript provided strongly typed structures for application data and shared state.

The prototype operates client-side using local application state and timed transitions rather than persistent storage or real backend message delivery. This allowed the implementation to concentrate specifically on evaluating the proposed interaction behaviours.

Modular CSS separates interface layout, message presentation, modal behaviour and visual message states, while GitHub was used for version control and incremental development.

Key Findings

Deletion Can Create Uncertainty

Users experienced uncertainty around what message deletion actually does and whether removed content can truly be considered gone.

Pre-Send Undo Increased Agency

The temporary undo mechanism was consistently valued as a meaningful opportunity to reconsider a message before delivery.

Undo Complements Deletion

Pre-send control was not treated as a replacement for post-send revocation. The findings instead supported providing control at multiple stages of the message lifecycle.

Transparency Builds Confidence

Clear feedback about system behaviour and deletion limitations improved users' understanding, trust and confidence in message-control features.

Broader Considerations

Message deletion and revocation involve more than interface design alone. The project also considered the legal, social and ethical implications of user control, data protection, system transparency and trust within private digital communication.

These considerations reinforced the importance of avoiding misleading guarantees and designing controls that communicate clearly what the system is capable of doing.
