Brick Breaker game

created using Java Swing

Project Overview

Brick Breaker is a Java Swing game built around real-time gameplay, multiple difficulty levels and configurable visual settings.

The player controls a paddle to keep the ball in play and destroy all bricks on the screen. If the ball falls below the paddle, the player loses a life. The game ends when all lives are lost or all bricks are cleared.

The project was designed using an object-oriented structure, with separate classes handling different game objects, interface elements and configuration options.

Key Features

Real-Time Game Loop

A Swing Timer drives a continuous update and render cycle, updating game logic and repainting the interface to provide responsive real-time gameplay.

Object-Oriented Architecture

An abstract GameObject base class defines shared properties and behaviour for game entities, with individual objects providing their own update and rendering implementations.

Centralised Object Management

A dedicated Handler manages active game objects and coordinates their update and rendering cycles through a shared GameObject collection.

Dynamic Difficulty

Five difficulty settings dynamically alter ball velocity, progressively increasing the speed and challenge of gameplay.

Event-Driven Controls

Swing key bindings respond to key press and release events, updating paddle velocity to provide responsive movement.

Game State Management

The game manages lives, countdowns, pause and resume behaviour, difficulty state, and win/loss transitions throughout gameplay.

Architecture

The game is split across multiple Java classes so that different responsibilities remain separated.

Game Objects

Classes such as Ball, Paddle and Brick represent the core objects used during gameplay.

Brick Behaviour

Separate brick classes such as NormalBrick and ColorChangingBrick allow different brick behaviour to be implemented without placing everything in one class.

Game Window

GameWindow and related interface classes manage the main application window and visual presentation.

Configuration

Dedicated selector classes handle difficulty and background selection independently from the core gameplay classes.

Challenges & Design Decisions

Keeping Gameplay Responsive

A key challenge was ensuring that the ball, paddle and bricks could update smoothly while the interface remained responsive.

Separating Responsibilities

Rather than placing the full game inside one large class, the project separates game objects, selectors, windows and level behaviour into individual classes.

Managing Difficulty

Supporting multiple difficulty levels required the game to handle different gameplay configurations while keeping the interface simple for the player.
